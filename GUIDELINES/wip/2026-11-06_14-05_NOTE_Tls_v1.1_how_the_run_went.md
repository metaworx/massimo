# NOTE Tls v1.1: how the run went

How the five blocks of [AP Tls v1.1](2026-11-06_12-42_AP_Tls_serve_tls.md) went
where they differ from the plan, under one `EXEC++` on 2026-11-06.

1. **Pull requests stacked, not one branch.**
   One pull request per block on one branch cannot coexist with the previous one open,
   so each block after the first has a branch of its own,
   based on the previous block's, and its pull request targets that branch:
   #53 (Block 1, `claude/tls`), #55 (Block 2, `claude/tls-2`), #57 (Block 4,
   `claude/tls-4`), #58 (Block 5, `claude/tls-5`), #59 (Block 3,
   `claude/tls-3`).
   They merge in that order; once a base merges and is deleted,
   GitHub retargets the next to `main`, else its base is changed by hand.
   `origin/main` was merged into `claude/tls` before each pull request
   and carried up the stack by merge commits.
2. **A defect found in existing code**
   (Block 2's merge of `main`):
   stage (b) had pasted three parameter definitions into two routes of
   `docs/api-v1-openapi.yaml` and given `POST /api/v1/update` a second `403`,
   so the file was no YAML.
   Fixed on `claude/tls` (`fix(docs): the OpenAPI description parses
   again, and the test checks it`): `TestOpenAPICoversRoutes` now parses
   the description and resolves every `$ref`.
3. **Block 1**:
   the helper's health drop-in is also rewritten when TLS is switched off or on
   without `-listen`, from the kept or default address;
   `massimo config` prints the TLS lines; `install -tls off` keeps the files.
   The README's "Command line" section lists no `serve` flags,
   so the TLS text is in "Server" only.
4. **Block 2**:
   the certificate's details went into the header's expert list (a "Certificate" row),
   not a Settings → Server panel, which is a plan of its own.
   `GUIDELINES/project/CI.md`'s nine pre-existing reflow warnings went
   with the reflow of that commit (line breaks only).
5. **Block 4**:
   `golang.org/x/crypto` was in the module graph already (indirect);
   the direct requirement added no module,
   and the armv6 binary grew by 704 KiB (14,549,154 bytes).
   The web UI computes the expiry warning from `/healthz`'s `not_after`
   in the page's language (two weeks, expired, none yet) instead of showing
   the server's English `warning`, which stays for the API and the log.
   The watch runs its first check at the start,
   so a server orders its certificate before the first client.
   `Files.Check` warns under 14 days for the files source too.
6. **Block 5** (added in v1.1 on the owner's instruction):
   the source reports `acme` like autocert's; the files are
   `<data>/tls/acme/<first name>.pem` and `.key` with a wildcard's star
   spelled `_wildcard`; the account key is autocert's `acme_account+key`;
   the order blocks the watch goroutine, never the server;
   a TXT record not seen by the resolver within ten minutes fails the
   order rather than being accepted blind.
   The Infomaniak hook uses the v2 zones API as `certbot-dns-infomaniak` does
   (`/2/zones/<zone>/exists`, `/2/zones/<zone>/records`),
   read from the plugin's source through the GitHub API, needs `curl` and `jq`,
   and reads the token from `INFOMANIAK_TOKEN_FILE` (`/etc/massimo/infomaniak.token`);
   `INFOMANIAK_ENDPOINT` is lego's name for the API's address.
   It ran against a fake of that API only.
7. **Block 3**:
   the UI had 44 absolute URLs after stage (b) added login.js,
   users.js and roles.js, not the 20 the analysis counted;
   `clientIP` became a method, and stage (b)'s `localPeer` is used as it is.
   The Synology and QNAP paragraphs of `docs/reverse-proxy.md` are from
   their documentation, not tried on a NAS.
8. **Tests under the race detector** found unsynchronised accesses in Block 5's
   test fakes, not in the code; the fakes serialise their handlers now.
9. **Sizes**:
   linux/armv6 13,828,258 bytes after Block 2,
   14,549,154 after Block 4 (`make cross`'s flags).
10. **The owner's day** is still to come:
    a real certificate from Let's Encrypt's staging directory on a box with a
    name and the router's forward (Block 4),
    and through the Infomaniak token (Block 5);
    the self-signed notice on a phone (Block 2).
11. **CI**:
    the macOS job's update step takes its rollback branch until a release on the
    alpha channel knows `-tls`, as CI.md says;
    the Windows job stays on plain HTTP.
