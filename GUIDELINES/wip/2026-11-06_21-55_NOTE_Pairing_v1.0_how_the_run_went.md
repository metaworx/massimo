# NOTE Pairing v1.0: how the run went

How the three blocks of [AP Pairing
v1.0](2026-11-06_20-35_AP_Pairing_copy_remove_panel.md) went where they differ
from the plan, under one `EXEC++` on 2026-11-06.

1. **Pull requests stacked, as AP Tls did.**
   #65 (Block 1, `claude/pairing` into `main`),
   #66 (Block 2, `claude/pairing-2` into `claude/pairing`),
   #67 (Block 3, `claude/pairing-3` into `claude/pairing-2`);
   they merge in that order.
   Main cut v0.9.0-alpha.1 during the run:
   `origin/main` was merged into `claude/pairing` and carried up by merge commits,
   and git's merge put Blocks 1 and 2's changelog bullets into the released section,
   so each merge moved them back under a new `[Unreleased]`.
2. **Block 1**:
   `CopyCommands` returns each command with what it copies,
   and an error for a room's value that cannot be encoded;
   `Writer.CopySettings` runs them,
   apart from `AddDevice`, which takes no `copy`,
   so that the move uses the same call and the answer says where a copy stopped.
   `copied.temperatures` lists the addresses.
   A room without another thermostat gets 0x40 alone, having nothing to copy,
   and the copy reaches the device even where the metadata does not list it yet.
   The fake Cube's `DiscardIf` (fakecube.go,
   named in Block 2's row) discards the 0x11 of the failure test;
   the copy's tests are in `config_api_test.go`,
   and the existing move and pairing tests send `"copy": false`.
3. **Block 2**:
   `RemoveCommands(snap, rf, typ)` finds the room itself (the metadata's,
   else the C line's) instead of taking room and members;
   its unlink keeps the 0x23 of the move's out-part,
   which the original software's delete does not send.
   `Snapshot.Forget` also drops the device's metadata entry from the copy,
   so that `Devices()` stops naming it between a proxy client's `t:` and its `m:`.
   Paths beyond the plan's table, each carrying a step it names:
   `internal/server/audit.go` (the action `device.remove`,
   for the audit and the command row),
   `server.go` and `followup.go` (the pump's `device_forgotten`:
   the follow-up stops re-reading a deleted device,
   whose `c:` the fake answers `A:` and the client would wait ten seconds on,
   and the proxy's clients get the `L` line),
   and `docs/proxy.md` (the `t:` forget).
4. **Block 3**:
   Settings → Cubes was hidden without the capability `cubes`,
   which the default manager lacks while it has `pair` and `structure`:
   it shows now for `cubes` or `pair` (`needs-cubes-or-pair`),
   the Cube's form, its notices and the found Cubes for `cubes` alone,
   and a test holds it.
   The plan's two UI commits are one,
   since the form, the texts and the stream's events serve both halves.
   The pairing sits at the top of the Cube's panel;
   a Cube other than the one shown has its pairing asked for every three seconds,
   the stream being per Cube;
   the log names the four new events; a device's actions wrap at 390 px.
   The suite's locators of the Cube's form (`test_cubes.py`, `test_settings.py`,
   `screenshots.py`) name `form.cube-form`,
   since the panel holds the pairing's form too.
   `run.sh` hands the suite the server's log (`UI_TEST_SERVE_LOG`),
   where `test_pairing.py` finds "settings copied" and "device removed".
5. **Screenshots**:
   Settings, Settings → Cubes and the Devices tab (1100 px, light and dark) and
   the slideshow were retaken.
   The Appearance shots differ on this machine from the committed set,
   and equally on a set taken from Block 2's tree,
   so they are font rendering and stay as committed.
6. **Quality pass**:

   `gofmt`, `go vet` for three platforms, `node --check` on the scripts,
   `json.tool` on the translations, `sh -n` on `run.sh`,
   `py_compile` on the test, the reflow and guideline checks,
   and a read of every diff.
