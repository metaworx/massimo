# NOTE Pairing v1.0: review fixes

A review of the three blocks of [AP Pairing
v1.0](2026-11-06_20-35_AP_Pairing_copy_remove_panel.md),
run in a subagent after the run of [NOTE Pairing v1.0:
how the run went](2026-11-06_21-55_NOTE_Pairing_v1.0_how_the_run_went.md),
found eleven defects;
the owner answered `EXEC` with D4-A and D5-A on 2026-11-06,
and each block's branch got its fixes, merged up the stack.

1. **D4-A, the copy's 0x40**:
   it goes directly to the device, as in the original software's log,
   but without the error reset and the retry,
   and its discard ends nothing:
   the copy goes on and the answer says `"mode_not_set": true`.
   Whether the Cube takes it from a device that was in a room before stays the
   owner's hardware check; a move no longer fails on it.
2. **D5-A, who may copy**:
   the copy needs `configure` as well as `structure`,
   asked before anything is sent,
   for a thermostat that is added or changes its room;
   `"copy": false` skips it,
   the page shows the switch with `configure` only,
   and a move in the Devices tab sends `"copy": false` without it.
3. **Two changes at once**:
   a lock per Cube around the links and the metadata of a device's add,
   move and rename, its removal, and a room's rename and delete,
   which read the metadata under it; the copies run after it,
   keyed by device.
   The last gate offered a re-read of the metadata before each write instead:
   the queue lets a waiting metadata write supersede another,
   so two writes built side by side would still lose one.
4. **Hidden devices**:
   `MoveCommands` takes the hidden set,
   so the links of an add and a move leave them out as well,
   which they did not before the run either (a defect in existing code);
   the restore planner passes none and is unchanged,
   so `internal/backup/plan.go` changed by its call alone.
   A device in room 255 by its C line is not unlinked when it is removed.
5. **A device the Cube keeps**:
   the snapshot keeps a forgotten device out of later `L` lines until a C line
   for it or a new greeting, as `docs/api-v1.md` says.
6. **A metadata leftover**, listed without a C line,
   is removed by its metadata entry alone.
7. **The page**:
   a copy that stopped keeps its error under Devices without a room;
   a failed reload no longer turns a success into an error;
   the question to remove is answered once;
   the countdown stops after three failed reads or when its Cube's panel is gone;
   the copy's help says that the room's other thermostats get its temperatures.
8. **The test** waits for the countdown's text.
9. **The documents**:
   the removal's 0x23 is named as Massimo's own,
   and the metadata before the copy as unlike the original software.
10. **Verification**:
    `MASSIMO_ENV_FILE=/dev/null go test ./...` and `-race` for `internal/server`,
    `internal/cubelan` (with the fake Cube),
    `internal/proxy` and `internal/cubeio`; `go vet` for three platforms,
    `make cross`, `make ui-test` 112 passed; no screenshot changed,
    as none shows what the fixes touched.
