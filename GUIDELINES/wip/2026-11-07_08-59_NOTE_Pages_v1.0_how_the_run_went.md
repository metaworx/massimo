# NOTE Pages v1.0: how the run went

How Blocks 1 and 2 of
[AP Pages v1.0](2026-11-07_08-27_AP_Pages_apt_site_github_settings.md)
went where they differ from the plan, on 2026-11-07.

1. **The branch.**
   `claude/pages` was made from pull request 75's head
   and merged with `origin/main` without a conflict:
   the Go stack already held the merges of #71 and #74,
   so the CHANGELOG conflict the plan's base expected did not come.
   Once pull request 75 was in `main`,
   the branch was reset to `main` at the owner's word, its merge commit dropped;
   no file change was needed, so there is no pull request.
2. **Block 1 made by the owner.**
   The implementing session's auto mode refused the three `gh api` writes
   as a change to a shared resource;
   the owner set Pages to GitHub Actions and the environment,
   and the session read them back.
3. **The environment's rules.**
   `github-pages` holds two deployment rules rather than the one tag rule `v*`:
   the branch `main`, GitHub's default,
   and the tag `v[0-9]*.[0-9]*.[0-9]*`, the `signing` environment's pattern.
   The tag rule matches every tag release.yml runs for,
   as Analysis 3 allows;
   the branch rule is unused, no workflow on `main` deploying to Pages,
   and was left as it is.
4. **Block 2.**
   The owner made the key and set both secrets;
   `gh secret list --env signing` shows `MASSIMO_APT_KEY`,
   `MASSIMO_APT_KEY_PASSPHRASE` and `MASSIMO_RELEASE_KEY`,
   names only, and no value reached the session.
