# NOTE LogLevel v1.0: after the merge with main

Before the pull request the branch merged origin/main,
which had gained AP Restart's settings reload (metaworx/massimo#88)
and AP CubeLost's reconnect attempts at Debug (metaworx/massimo#91).

1. **Step 4, serve's flag.** `serve -log-level` is a plain flag whose
   default is `MASSIMO_LOG_LEVEL`, as every other flag of serve is,
   rather than one that sets the variable as the global option does:
   the reload sets the file's variables again,
   and a flag kept in the environment could be overwritten by it.
2. **The reload.** `-log-level` is among `flagVars`, so a level the flag
   gave is not listed as waiting for a restart;
   without the flag, a `MASSIMO_LOG_LEVEL` the settings file changes is
   listed by `GET /api/v1/restart`, as D4-A has it (a restart only).
   `TestReloadListsTheLogLevel` checks both.
3. **The documents** name the failed attempts to reach a lost Cube among
   the Debug lines, and the CHANGELOG bullet says that a change in the
   settings file waits for the restart.
