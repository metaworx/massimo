# NOTE Logging v1.2: pi timing after

The last check of Block 8's Verification of
[AP Logging v1.2](2026-11-09_00-23_AP_Logging_log_sources_and_serials.md),
left to the owner's go, run on 2026-11-09 under the owner's `EXEC Pi, then retire`:

`docs/store.md` (sections 2 and 5, `events`) carries them.

## How it was measured

As [NOTE Logging v1.1: pi timing](2026-11-09_11-34_NOTE_Logging_v1.1_pi_timing.md)
describes, with these differences:

- **The copies:** made by the owner with the same command, at 15:48 on the Pi 5
  and at 15:50 on the Pi 1.
  The Pi 1's copy held 1009 events (debug 16, info 671, warn 322),
  the Pi 5's 172 (debug 11, info 159, warn 2).
  Both boxes still run `massimo` v0.12.0-alpha.1, so both copies were at
  schema 8, and each binary migrated its own copy of the copy.
- **The binaries:** the same uncommitted `TestPiTiming`, compiled for each box
  from `3d7588f` (`main` before #137, schema 10) and from `af84645`
  (#137, schema 11, the tree its merge `9c39f52` has).
  A dry run of both on the Pi 5, on the stand-in store of 600 events the test
  made, came first.
- **The service and its file:** untouched.
  The store files kept their times, both services stayed active,
  and the copies and binaries were deleted after the run.

## Findings

- **The page of warnings** reads the warnings alone:
  58 ms → 1.9 ms on the Pi 5, whose warnings are rare;
  99 ms → 75 ms on the Pi 1, whose warnings are a third of its rows,
  so the walk there was short before as well.
- **The page of errors**, of which neither box has any, reads every warning:
  153 ms → 2.0 ms on the Pi 5, 5.6 s → 1.7 s on the Pi 1,
  where 90,000 events hold about 30,000 warnings.
  The server writes no line at `error`, and the UI offers no such choice,
  so only `GET …/log?level=error` meets it;
  the plan's Analysis left an index of the errors out for that reason.
- **The insert:** no difference to measure on either box, at the copy's size
  or at 90,000 events.
  The largest batch on the Pi 1 still waits seconds for a checkpoint of the WAL,
  at 10 as at 11.
- **The errors page at schema 10** took 5.6 s this time, against 11.4 s
  (5.5 to 16.0 s) on the morning's copy:
  the same walk, the SD card's spread.
- **The migrations** from schema 8 took 2.1 s to open on the Pi 1 with or
  without 0011, so building its index costs nothing worth naming.

## Where the run went differently from the plan

1. **Pull request 137 merged during the run;**
   the binaries were built from its commit, whose tree is the merge's.
2. **The owner made the copies** before they were asked for,
   right after the signal; the run used them.
