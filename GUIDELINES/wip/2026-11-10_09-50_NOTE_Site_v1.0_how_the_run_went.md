# NOTE Site v1.0: how the run went

Where the `PLAN++ Site` run of 2026-11-10 went differently from the plan,
and what it found.

1. **A check more: dead links.** A link to a file the commit does not have
   would have become a GitHub URL that answers 404, past the link check of
   the pages; `site.py` now fails on it before converting, with the
   document and the line.
2. **The OpenAPI YAML is not copied.** `md_html.py` sends a link to a file
   that is not a page to GitHub at that commit, so a copy on the site would
   have no link to it; the YAML is read on GitHub.
3. **`build.sh --no-docs`.** `packaging/apt/test.sh` runs in CI's
   `deb` job, whose checkout has no guidelines submodule; it builds the
   repository and the pages alone, and the docs are the `Site` job's.
   The link check runs only where the docs are built, since the home now
   links `/docs/`.
4. **Headings wrap**, a fix under Block 3 ("A heading holding a long route
   wraps at a phone's width"): `docs/api-v1.md`'s
   headings are routes in code, and made its page 600 px wide at 390;
   every one of the 26 pages fits now, light and dark (checked with
   Playwright at 390 px, and the index at 1100).
5. **Not exercised before the merge:** the download of a pool by
   `pool.tsv` (in the test every package is `included`), the `site` job of
   `release.yml` and the deploy. The first run of `main` after the merge
   builds the site and, with no release carrying the index yet, deploys
   nothing; the owner's next `make release-alpha` is the first deploy.
6. **The apt index of a release is needed for a deploy from `main`**, and
   the first one comes with that release; until then the docs reach the
   site only through a release.
7. **For the owner:** `docs/reports/windows-test-2026-11-05.md` names the
   owner and the owner's machine in its first lines (WorkDocs' NOTE); it is
   in the list of documents, so the site will publish it at the first
   deploy.
8. `actionlint` ran from its Docker image (`rhysd/actionlint`); the new
   workflow and jobs gave no finding, the existing ones their old
   shellcheck notes.
