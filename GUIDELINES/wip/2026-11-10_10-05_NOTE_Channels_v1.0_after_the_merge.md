# NOTE Channels v1.0: after the merge

Decisions and fixes after pull request #159 merged (2026-11-10),
for AP Channels v1.0 (`2026-11-10_07-28_AP_Channels_devel_nightly_flavours.md`).

## Fixes on `main`, at the owner's word, without a pull request

- `fix(pipeline): The release runs although Changed paths is skipped`:
  ci.yml's Release job had no status function in its `if:`;
  GitHub's implied `success()` was false because Changed paths,
  up its chain, is skipped on every push, so the merge's run made no devel build
  (and a tag's would have released nothing).
- `ci(pipeline): A rolling build's manifest is replaced after its files`.

The first `release/devel` came from the run of the first of them on 2026-11-10 at 08:49 UTC;
a tag with a `/` in its name works with `gh` and the API,
and a devel build's `update -check -channel devel` finds and verifies it.

## Decisions (EVAL answers, 2026-11-10)

- **D20-A:** a rolling release stays replaced in place,
  the manifest and its signature uploaded after the other files.
  Not B, draft, publish and delete the old one: every merge would notify
  the release's watchers.
- **D21-A:** the nightly build is rebuilt, not retested:
  its binaries carry the flavour `nightly`, and get the day's Go patch.
  Not B, the devel build's files with a new manifest.
- **D22-A:** a box with neither `MASSIMO_UPDATE_CHANNEL` nor `update.channel`
  follows its binary's flavour, so that a fresh install keeps updating like
  what was installed. Not B, a fixed default; not C, no default.
