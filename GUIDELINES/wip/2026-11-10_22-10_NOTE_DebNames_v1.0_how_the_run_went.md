# NOTE DebNames v1.0: how the run went

Blocks 1 and 2 ran under `PLAN++ D2-B` on 2026-11-10, on the branch
`claude/deb-names`; Block 3 waits for the owner's word.

Where the run went differently from the plan:

1. **The fragments' names** follow COMMIT.md 5.5's preference, the branch
   name: `CHANGELOG.d/Fixed/claude-deb-names.md` (Block 1) and
   `CHANGELOG.d/Fixed/claude-deb-names-check.md` (Block 2), not the plan's
   `deb-asset-names.md` and `release-asset-names-checked.md`.
2. **The check is a script**, `packaging/release-assets.sh <tag> <file>...`,
   which release.yml calls at the three places the plan names, rather than
   shell repeated in two steps: it can be run by hand against a release.
3. **What the rolling job keeps** where the check fails: the uploads have
   happened (the binaries and the manifest are the new build's), the tag
   has not moved and nothing is deleted. The plan's "keeps its old files"
   holds for the files GitHub renamed, not for the release as a whole.

Measured:

- `make packages VERSION=v0.13.0-alpha.2`: `massimo_0.13.0.alpha.2_<arch>.deb`,
  `dpkg-deb -f` Version `0.13.0~alpha.2`; a rolling version
  `v0.13.0-alpha.2-1-g7d170c3` gives `massimo_0.13.0.alpha.2.1.g7d170c3_<arch>.deb`,
  the form `release/nightly`'s debs already carry.
- `make release VERSION=v0.13.0-alpha.2 FLAVOUR=alpha`: `SHA256SUMS` and
  the manifest name the dotted files, `sha256sum -c SHA256SUMS` passes.
- `packaging/release-assets.sh v0.13.0-alpha.2` passes on the dotted
  names and fails, exit 1, on `massimo_0.13.0~alpha.2_amd64.deb`.
