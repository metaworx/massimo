# NOTE OneLog v1.1: ci fixes and block 3

What CI's first run of Blocks 1 and 2 found, and how Block 3 went where it
differs from the plan.
It corrects item 2 of `wip/2026-11-11_11-35_NOTE_OneLog_v1.1_blocks_1_and_2_run.md`.

1. **launchd's stderr file is the service user's, not root's.**
   The Mac's daemon did not start with `/var/log/massimo-serve.stderr.log`
   `root:admin` 0640: launchd opens `StandardErrorPath` as the job's user,
   which is why an older install made `serve.log` `_massimo`'s.
   `massimo install` now makes it `_massimo:admin` 0640;
   it stays in `/var/log`, which only root may write,
   so it still cannot be swapped for a link.
   The template test prints it when a check fails.
2. **CI's Windows job looks for its line in two files.**
   The update to the released alpha and the rollback each start a binary of
   the other log format, which rotates `serve.log`, as Block 2 means it to:
   `update helper started` is then in `serve.log.1`.
3. **A test's order.**
   `internal/logfile`'s format test ran its two writers from a map,
   and the plain one's new file is plain;
   they run in a fixed order now.
4. **Block 3 fixed a defect in passing.**
   serve gave the queue no logger, so its lines (`room woken up`,
   `proxy client's command sent`, the duty cycle's waits) went to Go's
   default logger on stderr: never into the `-log` file,
   and outside `-log-level` and the format.
   The queue now gets the server's logger, with `source=queue`.
5. **Block 3's sources** are a package's, as the plan's first sentence says:
   `system` (serve's own), `server`, `cube`, `queue`, `proxy`, `store`,
   `tls`, `announce` and `push`, with `cube=` where a part serves one Cube.
   The plan's `api` and `discovery` are the server's lines and say `server`.
   `serving cube` said `source=` for where the Cube came from;
   it says `from=` now.

The fixes' run passed every check of the pull request,
the Mac's and Windows' included.
