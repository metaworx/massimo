# NOTE OneLog v1.1: events view and mac logs

The owner's decisions of 2026-11-11 (`EXEC D16-C`, `D17-A`,
then `EXEC++ D18A D19-A`), taken before Block 4.
They change steps of Blocks 2 and 4; the blocks stand.

1. **D16-C: `events` is renamed `log`, and stays readable as a view.**
   Migration 0014 is the first that would have raised `min_reader`
   (D8-A was decided before that was known):
   a release before it would refuse the store,
   and the update helper's rollback and CI's Windows update test with it.
   0014 keeps `min_reader` 1 and leaves a view `events` over `log`,
   with `INSTEAD OF` triggers for the insert, update and delete that older
   releases make, so that they still write the log.
   Through a view SQLite counts no changed rows,
   so an older release's prune removes one chunk per Cube a pass and logs
   no `events pruned`; the next pass goes on.
   The view goes in a later migration that raises `min_reader` anyway.
2. **D17-A: the Mac's stderr file is `/var/log/massimo/serve.stderr.log`.**
   launchd opens it as the job's user (item 1 of
   `wip/2026-11-11_12-38_NOTE_OneLog_v1.1_ci_fixes_and_block_3.md`),
   so a link put there gains `_massimo` nothing,
   and the directory's 0750 keeps others out.
3. **D18-A: no move of the old stderr file.**
   `/var/log/massimo-serve.stderr.log` exists only on this branch;
   a released Mac's stderr went into `/var/log/massimo/serve.log`,
   which serve rotates into `serve.log.1` at its first start
   (the format changes), so its retention takes it.
4. **D19-A: Homebrew's service passes `-log`.**
   `brew services` runs as the Mac's user, who cannot write `/var/log`:
   the formula's service passes `-log #{var}/log/massimo/serve.log` and
   `-log-process-format none`, so that serve writes and rotates the log in
   brew's prefix as everywhere else; `var/log/massimo.log` keeps only what
   serve prints before its log.
