# NOTE OneLog v1.1: no client column

The owner's decision of 2026-11-12 (`EXEC ready D20-A`),
after the plan's nine blocks.

**D20-A: the log has no column of the client's address.**
The address stays where it is kept:
`audit.remote` for a request of the API or the web UI,
which a log row reaches through its `command_id`;
the command's `request` for a line a proxy client passed on;
the summary of the proxy's rows and of the sign-ins.
A column would be a content column under the store's rule (`rule_test.go`),
so no index and no filter could serve it;
every user with `read` would read it on the log,
where the address of a change is the audit's today;
and it would repeat what the rows already reach.
It stays cheap later: an additive column, `min_reader` 1.
Not taken: B, the column as content, shown to an auditor;
C, the column indexed and filtered, which would need addresses to be
structural in the content rule.
