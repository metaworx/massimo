# NOTE Channels v1.2: block 14 switch test

For AP Channels v1.2 (`2026-11-10_07-28_AP_Channels_devel_nightly_flavours.md`),
Block 14, the apt helper switching the suite.
Two things went differently from the plan:

- **The switch is tested in `make apt-test`, not `make deb-systemd-test`.**
  The plan's verification names a switch from `alpha` to `devel` and back
  in the systemd container against a local repository.
  `packaging/apt/test.sh` already runs the Debian package's update helper
  in a container against a local repository it signs with throwaway keys,
  the numbered and the rolling one since Block 11,
  and runs the helper's command as its unit has it;
  systemd adds nothing the switch needs.
  So its last container, "apt suite switch test", does it:
  a box on `alpha` asks for `devel` and gets the newer package,
  the source then naming `devel` and the rolling keyring;
  `nightly`, which that repository lacks, fails `apt-get update`,
  and the source is put back on `devel`;
  back to `alpha`, the source names the numbered keyring again,
  and nothing is downgraded.
  It passed on 2026-11-12 on `debian:trixie-slim`.
- **The helper does not upgrade the keyring package.**
  A switch to `devel` or `nightly` needs
  `/usr/share/keyrings/massimo-rolling-archive-keyring.gpg`,
  which only the keyring package of Block 11 carries.
  The numbered suites carry that package only from their next release's
  run on; until then a box on `alpha` refuses the switch, the source
  unchanged, and the helper's last run says so,
  with `sudo apt update && sudo apt install massimo-archive-keyring`.
  The helper's apt commands stay as they were, `massimo` alone.
