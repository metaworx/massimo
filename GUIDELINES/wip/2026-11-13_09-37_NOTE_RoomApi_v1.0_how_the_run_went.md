## Where the work differs from the plan

1. **The audit names a virtual wall thermostat's command by its room,**
   `room:<id>`, as the room routes do, without the plan's `"via"`.
2. **A room without a reported thermostat:** its virtual wall thermostat is
   `reported: false`, and its state holds `window_open` alone. `consistent` is
   given only once a thermostat has reported.
3. **An address the owner set** that a real device takes later falls back to the
   room number, then to the range `000100`–`0001ff`.
4. **The web UI lists the virtual wall thermostat after the real devices** in
   expert mode, not first: a hidden first row kept the UI tests' selectors waiting.
5. **The programme editor's UI test stands in the `412` in the browser,** so that
   the fake Cube's programme stays as the other tests expect it.
6. **`proxy_virtual` is kept in a table of its own,** `cube_options` (migration
   0018), not as a column of `cubes`: a column broke the migration tests, which run
   today's code against older schemas.
7. **Proxy commands without a real wall thermostat:** settings (0x11, 0x12),
   display, lock, links and group addressed to a virtual wall thermostat in a room
   without a real one are answered by the proxy and sent nowhere. The plan sent the
   settings to the room's config; a group 0x11 is not confirmed on hardware.
8. **Boost is in a room's ⋯ menu,** not in the mode row, which has no room for a
   fourth button at 390 px.
9. **Block 9 ran from manual,** on the owner's further word, since the test room
   was in manual and getting to auto would have been another radio write.
10. **The test room's devices boost 30 minutes at 100 %** by their own settings,
    not the 5 minutes at 80 % of the earlier captures; both returned to manual by
    themselves (`docs/portal-protocol.md`).

## Found on the way

1. **A data race:** the pump and a settings change through the API both published
   virtual wall thermostat events. CI's race job found it; a mutex fixed it before
   the merge.
2. **A command meeting a poll fails:** a queue command sent while the poll's `l:`
   or a re-read's `c:` waits for the Cube's reply fails with `cubelan.ErrBusy`,
   without a retry. This predates the plan. The room tests poll slowly around their
   writes, and the fix was offered as a separate task, which the owner started.
3. **Not taken:** the Home Assistant integration's request for a `features` list
   in `/healthz`, which is not in the plan, waits for the owner.
