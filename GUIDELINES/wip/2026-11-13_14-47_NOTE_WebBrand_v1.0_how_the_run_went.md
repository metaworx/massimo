# NOTE WebBrand v1.0: how the run went

How [AP WebBrand v1.0](2026-11-13_14-23_AP_WebBrand_the_mark_in_the_web_ui.md)
went under the owner's `PLAN++ as recommended` of 2026-11-13,
in pull request #220, where it went differently from the plan.

1. **The logo is drawn by a script, not written into each place**
   (Block 3).
   The plan had the drawing in the markup of each place.
   The page's partials may each be listed once (`uiPartials`),
   and the apps copy `connect.html` as it is,
   so the same markup would have been copied by hand four times.
   `brandMarks` in `components.js` draws it over every element marked
   `data-brand`, on both pages; the word is in the markup,
   which is also what shows before the script has run.
2. **`brand.css` names the logo's proportions as a token too**
   (`--brand-logo-ratio`, Block 3, in the tool and its file),
   so that the word's box is the logo's before the drawing has come,
   and nothing moves when it does.
3. **`*.ico` is binary in `.gitattributes`** (Block 1):
   the rule for `internal/server/ui/**` takes every file there for text,
   and would have changed the favicon's line endings.
4. **The brand and its version are centred on one line**
   (Block 3), no longer on a common baseline: the logo has none.
5. **Verification:**
   - every other scope of the tool wrote its files byte for byte as v1.0.0 did
     (`svg`, `png`, `tile`, `favicon`, `homeassistant` of `grayorange`),
     and a second `make ui-brand` wrote the same bytes again;
   - the sprite, the favicon and the word without the sprite were looked at in
     Chromium, light and dark;
   - `test_brand.py` counts the drawing's orange hands in the header's pixels,
     by a screenshot drawn into a canvas in the page;
     the word without the sprite is tested with a sprite that draws nothing,
     since a refused file is a console error the browser names no file in,
     which the suite's guard cannot excuse;
   - the screenshots were retaken (`make ui-screenshots`).
