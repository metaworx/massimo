# NOTE FreshRun v1.0: how the run went

Where the run of AP FreshRun v1.0 went differently from the plan,
and what it measured.

## Block 1

As planned, PR #218, merged by the owner on 2026-11-13.
`postDiscovery` posts up to three times.
Under 64 busy loops the follow test passed 200 runs out of 200,
and the full suite passed with the load still running.

## Block 2

- **Its own branch and pull request**, `claude/fresh-run-api`,
  not `claude/fresh-run`: D3-A on the gate after Block 1, 2026-11-13
  ("a new branch from main after #218 merges, with its own PR").
- **A test's last step removed:** `TestDiscoveryFindsUnconfiguredCubes` ended with
  "two calls during one run share its result", two `POST`s sent at once.
  Under D2-B the second call to arrive gets the run after the first,
  so the two answers differ by design.
  `TestACallDuringARunGetsTheNext` tests the sharing instead, with the calls made
  while a run is going (a 1 s wait for the margin), and the loop's call sharing the run going.
- **`postDiscovery`** fails a test where the answer's run began before the call,
  as planned, so every test that posts checks D2-B.
- **Measured** on jaguar beside 64 busy loops:
  the follow test 200 runs out of 200;
  `TestACallDuringARunGetsTheNext` and `TestDiscoveryFindsUnconfiguredCubes`
  60 runs each out of 60 with `-race`.
  The test gate, `go test -race` over `internal/server`, `make cross`
  and `make lan-test` (its searcher posts to `/api/v1/cubes/discover`) passed.
