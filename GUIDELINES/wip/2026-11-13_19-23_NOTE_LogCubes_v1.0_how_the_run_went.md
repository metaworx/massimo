# NOTE LogCubes v1.0: how the run went

Where the run of AP LogCubes v1.0 went differently from the plan,
and what it measured.

## Before the blocks

- **Main moved during the run:** retirements and LostSearch (#225, #226)
  came in after the plan was registered locally.
  The registration was made again on the new main and pushed;
  Block 1, not yet pushed, was put on top of it again, unchanged,
  and its tests passed on the new base.
- **The fix (D6-A)** is pull request #227, made from the new main;
  the branch merges it, so the pull request of Blocks 1 to 3 shows its
  commit until #227 is merged.

## Block 2

- **The S/N in expert mode** is a span of its own (`.log-sn`) before the
  radio address's, not the radio address's text,
  so that the tests and the filter that read the radio address read it alone.
  It is left out where the line already names the device by its S/N.
- **A type that stands in for a name** starts with a capital letter
  (`upperFirst`): the English type names are lower case for the running
  text of the log ("Removed radiator thermostat …").
- **The reload test** now reads the type, not the S/N,
  where the lines kept no name before the rooms came:
  D4-A puts the type before the S/N.

## Block 3

- **The Cubes choice is in `index.html`**, a bare `<select>` beside the
  log's other choices, which are all there, not a `.field` in
  `ui/partials/log.html` as the plan said: the partial holds only the
  line's template.
- **`fetchRooms` in `app.js`**, beside the plan's files:
  `loadRooms` and the log's every-Cube rooms load a Cube's rooms one way.
- **A device chosen by its radio address** under All Cubes stays as it
  is, in the choice by its address (D11-A), where under this Cube an old
  link's radio address takes the S/N.
- **The test's lines are its own:** the second Cube, added through the
  API, never connects, and the lines of `GET /api/v1/log` are the test's,
  answered in the page's place, after a first answer from the server;
  the poll is called from the test, as the timer's 10 s would slow it.

## Checks

- Block 2: the log's UI tests (92) and the whole UI suite (648) passed,
  each at the first pass; `go test ./internal/server/`.
- Block 3: its test and the naming tests (16), the whole UI suite (652),
  and after a last tidying of `log.js` the log's UI tests again (96),
  each at the first pass; `go test ./internal/server/`, `node --check`.
- No Go code changed after Block 1, so `make cross`, vet and the race run
  were not repeated for Blocks 2 and 3.
