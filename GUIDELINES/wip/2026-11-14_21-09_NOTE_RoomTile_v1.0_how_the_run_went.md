# NOTE RoomTile v1.0: how the run went

The run of `PLAN++ split` on 2026-11-14 in its own session,
Blocks 1, 2 and 4 on `claude/room-tile`, pull request #262,
and where it went differently from the plan.

## Not run

- **Block 3 (ErrorReset)** waits for D102,
  which the hardware session "Investigate the MAX! Cube's transmit error
  on hardware" settles; nothing of it is on the branch.

## Block 1

- **The keys came with their blocks.**
  Each block's i18n keys are in its own commit, in all six languages,
  since its tests need them; Block 4 is `docs/ui.md` alone.
  `mode.holiday`, `room.holidayTitle` and, in Block 2, `room.until` went
  with the button and the line that used them.
- **The tests are a file of their own**, `tools/ui-test/test_room_more.py`,
  rather than in `test_rooms.py`.
  `test_send.py`'s Boost test looked for `details.menu` in a tile,
  which More now is too: it opens the ⋯ menu by its place.
- **The arrow keys** are `menuArrows` in `components.js`,
  `pickerMenu`'s own handler made a helper that More uses too.
- **Hold (Manual)** is kept per tile until the page is loaded again,
  not as a setting: the plan left it open.
- **Eco and Comfort on holiday** send the holiday with its end kept,
  the room's mode as D99 asks; the plan named Auto and Manual only.
- **Fixed on the way:** `closeMenu` closed the first menu of a tile,
  the problem pill where it had one; it closes every open menu of it.

## Block 2

- **The line "🧳 until …"** beside the mode buttons went:
  More says the same, and two would have said it twice.
- **The end's form** (`fmtUntil`): day, month and time in the page's
  language, "24.12., 18:00", the year where it is not this one;
  the device list's end in the same form, where it was the Cube's
  "YYYY-MM-DD HH:MM".
- **A long More** pushed the tile's tools onto a third line at 1100 px:
  the modes take the row beside the tools and wrap there,
  More under AUTO and MANU, the tools beside both.
- **The holiday in the pill** is an item of its own kind (`holiday`,
  the suitcase, the holiday's violet), named after the problems in the
  pill's label; in a room whose modes differ, a thermostat on holiday
  shows its holiday in place of its mode.
- **No room of the fake Cube has two thermostats:**
  the test of modes that differ adds a second one in the page.

## The gate

- **A time bomb in an existing test.**
  The first full UI run failed `test_cube_panel_pill` in all four cases:
  it took the server's Cubes as they were for "nothing wrong: no pill",
  and the fixture's window contact is open,
  which warns once the server has seen it open for five minutes
  (`view.WindowWarnAfter`, AP Signs).
  The new test file moved the schedule so that its worker reached the test
  later than that.
  The test now empties the Cube's device problems at the route for the
  check, as `test_cube_problems` does in the page;
  it passed after a 5.5-minute wait.
  A commit of its own, citing Block 4.
- **`test_log_names_devices_once_the_rooms_come`** failed once (390-de)
  in the same run, at two different asserts on its two tries,
  and passed alone and in the second full run.
- **`make race`**: `internal/server` hit the 10-minute timeout under a load
  of 40 (the other sessions' suites);
  alone with `-race -count=1 -timeout 40m` it passed in 597 s.
- **The rest:** `go test ./...`, gofmt, the three `go vet`,
  `make cross`, `make ui-test` (744 passed, the second run),
  and the guidelines check (12, all well).
