# NOTE EarlyHup v1.0: how the run went

Where the run of AP EarlyHup v1.0 (Block 1) went differently from the
plan, and what it measured.

- **The built-serve test asks for more than the plan said.** The plan
  accepted the warning or, for a SIGHUP that came late, a rotation; the
  test now requires the warning for a SIGHUP sent at "store created",
  and a rotation for a second one sent once the server started.
  It is deterministic here, because the store's migrations follow
  "store created".
- **The test harness waited for the API.** `startBuiltServe` returned only
  once serve logged "api listening", so a SIGHUP "during the start" from a
  test came after it, on main's code as on the fix. It is split:
  `launchBuiltServe` returns at once, and `startBuiltServe` is it with the
  wait, so its other callers are unchanged.
- **On main's code** the test fails 5 of 5, "serve ended before logging …:
  signal: hangup"; with the fix it passes 20 of 20. Outside the tests, a
  SIGHUP at "store created", "schema migrated" or "node key created" ended
  main's binary 15 of 15 times, and the fixed one logged the warning
  15 of 15 times.
- **A test of the in-process catch** (`TestCatchSighup`) sends SIGHUP to the
  test process itself, so it is Unix only, beside the built-serve test in
  `sighup_unix_test.go`; the handler's own test (`TestHupReloadBeforeReady`)
  runs everywhere.
