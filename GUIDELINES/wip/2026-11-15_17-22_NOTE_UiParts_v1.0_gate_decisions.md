## How the blocks are run

The owner's word: the blocks are implemented by sub-agents, or by
sessions of their own, running Opus 5.5.
The session that wrote the plan registers it, briefs them and checks
what they hand back.

## Block 1 ends with main merged and the cut made again

The owner's word: "be prepared to merge main back into the Block 1 at
the end and re-cut with the then-up-to-date code".

So the tool of Block 1 is made to run again on a tree it has cut:

- **The map names every top-level declaration** of a script it cuts,
  the ones that stay too. A declaration that arrived since stops the
  tool until the map places it.
- **A declaration that is in the script again**, as a merge of main
  brings it back where main changed it, takes the place of its copy in
  the script it was moved to.
- Block 1's last step before its pull request is: merge main, run the
  tool, verify again.

## A step of the recipe for an open branch

Step 3 merges the move with `-X ours`, not with `-s ours` as the plan
says.
`-s ours` drops whatever else the move's commit carries, its CHANGELOG
fragment for one, and the branch's later merge into main would then
delete it there.
`-X ours` takes the branch's side only where the two differ, which is
in the moved code the branch had changed.
