# NOTE UiParts v1.0: how Block 1 went

Where Block 1, Regions, went differently from the plan, and what
verified it.

## What it made

Six scripts are nineteen, by moves alone:

| Cut | Into |
|---|---|
| `app.js` | `app.js`, `header.js`, `home.js`, `prefs.js` |
| `tiles.js` | `rooms.js`, `tiles.js`, `devices.js`, `unlisted.js`, `house.js` |
| `cubes.js` | `cubes.js`, `cube-panel.js`, `pairing.js` |
| `update.js` | `update.js`, `maintenance.js`, `system-info.js` |
| `log.js` | `log.js`, `pages.js` |
| `theme.js` | `theme.js`, `appearance.js` |

Ten regions of `index.html` are partials, and `tools/ui-split/` holds
the tool, its map and the recipe for an open branch.

## Different from the plan

1. **Who did it.**
   A sub-agent on Opus 5.5 did the block without a commit, each step
   recorded as a tree; the commits were made from the trees after the
   commit gate.
2. **The page served is not byte for byte the same.**
   Each new partial that had no opening comment got one naming its
   script, eight lines in all. With the comments left out the page is
   the same.
3. **A few items sit elsewhere than the plan's table says,** by who
   uses them:
   - `selectCube`, `isConfigured` and `applySettings` stay in `app.js`;
   - `toggleDevices`, `deviceIcon` and `deviceProblems` stay in
     `tiles.js`;
   - `hostPort`, `cubeAction` and `addCube` go to `cube-panel.js`;
   - the colour arithmetic and the `choose…` functions stay in
     `theme.js`.
4. **One order changed, in the step that is not a pure move.**
   `initUpdate` became three functions, each with its own listener:
   when Maintenance is shown, the software update's load starts before
   the announcement's, the restart's and the reboot's. They do not
   depend on one another.
5. **Thirteen commits, and the changelog bullet once.**
   The bullet is in the first; the others rest on it. A thirteenth
   commit corrects five comments in the test files, kept out of the
   others so that the suite ran on tests nobody had touched.
6. **The tool does more than the plan asked:** `--compare` (the cut of
   one tree is another), `--list`, a self-test, and a stop where
   top-level code would need a script that loads after it.

## Main merged and the cut made again

As the owner asked. Main had changed four of the six scripts and
`index.html`.

- **The scripts:** the merge put main's changed functions back into the
  scripts cut; the tool moved them again.
- **Two functions new on main** stopped the tool until the map placed
  them: `otherNetworkEls` (`home.js`) and `rfLabel` (`log.js`).
- **One function main had deleted** the tool did not see: `showSearch`
  stayed as its copy in `home.js` until `TestUIPage` named the id it
  read. It is taken out, and the tool's `README.md` says how to find
  such a one.
- **`index.html`:** main's two changes were to markup that had moved to
  partials, and were made there by hand: the search's status line out
  of the header, and the page's toast.
- **Comments:** seven that main's functions brought back named the old
  scripts, and were corrected again.

A branch that is open on the UI has the same three things to look at
when it follows the recipe: an item it adds, an item it deletes, and
markup it changes in a region that is now a partial.

## What verified it

- **Before the merge:** every cut is the tool's output on its parent
  (`--compare`), and by a comparison of every line no code line was
  lost or added but the new scripts' `"use strict";`. The whole UI
  suite passed twice with no test changed, 956 runs each.
- **After the merge:** every code line of main's six scripts is in the
  cut, but for the init functions and the comments this block changed.
  `go test ./...` (26 packages), `go vet` for Linux, Windows and macOS,
  `make cross`, the tool's `--check` and the guidelines' twelve checks
  pass.
- **Not run after the merge:** the whole UI suite, at the owner's word.
  CI runs it on the pull request.
