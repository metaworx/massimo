# NOTE UiParts v1.0: how Block 4 went

Where Block 4, ApiTypes, went differently from the plan, a defect it
found in the OpenAPI file, a decision left open at its gate, and what
verified it.

## What it made

`tools/apitypes`: a Go program in the main module that writes
`internal/server/ui/src/api.d.ts`, one exported declaration per schema
of `docs/api-v1-openapi.yaml`, in the file's order.
`make api-types` runs it, and `go run ./tools/apitypes -check` says
whether the file is current without writing it.
The file is kept by git: 85 declarations at the merge.

An object is an interface, a property optional unless required;
`allOf` is `extends` or an intersection, `enum` a union of literals,
`nullable` is `| null`, `additionalProperties` a `Record`;
a description and a format are JSDoc.
Any other keyword stops the program, naming the schema and the keyword.

## A defect it found

Fifty descriptions in `docs/api-v1-openapi.yaml` stood unquoted inside
a flow mapping and held a comma. YAML ended each at its first comma and
read the rest as keys without a value, 61 of them. The generator stopped
at the first, which is how they came to light.

Each is in double quotes now, in a commit of its own:
`docs(api): The OpenAPI file's descriptions with a comma are quoted, and read whole`.
A second YAML parser read the file before and after: those fifty
descriptions run on from where they were cut, the 61 keys are gone,
and nothing else differs.

## Different from the plan

1. **Who did it.**
   A sub-agent on Opus 5.5 wrote it in the session's own worktree,
   without a commit; the commits were made from recorded trees after
   the gate.
2. **Three commits, not one:** the OpenAPI file's correction, the
   generator with its file, and the documents.
3. **The test is in `tools/apitypes`,** not beside
   `TestOpenAPICoversRoutes`: `TestGeneratedFileCurrent` fails while
   the file is not current and names `make api-types`.
   `TestMapping` and `TestUnmapped` hold the mapping on small schemas.
4. **`docs/ui.md` too,** beside `docs/api-v1.md`: "How the page is
   built" names the file and its `import type`.
5. **No sample is kept.** The plan's sample that reads a Cube and a
   device was written for the check and removed after it.
6. **Main changed the OpenAPI file meanwhile:** a schema, `Mismatch`,
   and two properties. The merge of main wrote the generated file
   again, from 84 to 85 declarations.

## A decision left open

**D177, fields the API always sends.**
The OpenAPI file marks few properties as required, so at the gate 543
of the 564 generated properties were optional, and a part must allow
for `undefined` on nearly every field.

- **A (recommended).** Each region's block marks as required the fields
  its part reads and the API always sends, checked against the route's
  Go code.
- **B.** One pass over all schemas, as a block of its own before
  Block 5.
- **C.** Leave them optional.

Not answered at the gate. It matters from Block 5 on.

## For the blocks that move a region

- **A change to a schema writes the file again:** `make api-types`, in
  the same commit. `go test` fails until then.
  A branch that merges a schema change from main does the same after
  the merge.
- **63 answers and bodies have no named type.** The OpenAPI file gives
  them inline and has no `operationId` to name them by;
  `GET /api/v1/cubes` is one, a list of a Cube or a found Cube.
  A part writes such a type from the named ones, or its block names the
  schema in the OpenAPI file.
- **`make ui-check` does not run the `-check`:** `go test` holds the
  file current, and the type check needs no Go.

## What verified it

- **That it bites:** a sample with a misspelt field of a `Device`
  failed `make ui-check`, which named the field and the right one;
  spelt right, it passed.
- **That a stale file is caught:** after the merge of main the `-check`
  failed on main's schema change until `make api-types` had run.
- **After the merge of main:** `make ui`, gofmt, `go vet` for linux,
  windows and darwin, `MASSIMO_ENV_FILE=/dev/null go test ./...`,
  `make cross`, `make ui-check`, the `-check` and the guidelines'
  twelve checks pass. The merged OpenAPI file has no key without a
  value beside a description.
- **Not run:** the UI suite. Nothing in the page changes; the pull
  request's run is CI's.
