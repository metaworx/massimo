# NOTE UiParts v1.0: how Block 5 went

Where Block 5, Cubes, went differently from the plan, the decisions
taken at its gate, the owner's rule on reuse, and what verified it.

## What it made

- **`ui/src/shared/`,** seventeen files: what every region needs to
  become a part. `docs/ui.md`, "How the page is built", lists each
  with its properties.
- **`ui/src/cubes/`:** System settings → Cubes and Cube settings as
  parts, built once per Cube and place and updated in place.
- **Gone:** `cube-panel.js`, the partials `cube-panel.html` and
  `found.html`, `cubesUI` and the code that put a redraw off.
  `cubes.js` keeps the region's plain names, which call the part.
- **`tools/ui-test/test_cube_updates.py`:** the reported fault and
  D126's two defects.
- **The guard's list** holds six regions, where it held eight.

## Decisions at the gate

The owner, 2026-11-16:

- **D177-A, fields the API always sends.** Each region's block marks
  as required, in the OpenAPI file, the fields its part reads and the
  API always sends, each checked against the route's Go code, and
  writes the types again with `make api-types`.
- **D178-A.** A test, `TestSharedPartsKnowNoRegion`, holds that a file
  under `ui/src/shared/` imports from that directory, from Preact and
  from the API's types alone.
- **D179-A.** A closed Cube panel keeps what is typed in it until the
  page is left. Before, the next poll threw it away.
- **D180-A.** The rule on reuse, below, is in the project contract,
  "The web UI", v1.13.0.

## The owner's rule on reuse

**Block 5 and every later block create reusable components where
possible** (the owner, 2026-11-16).
How Block 5 applied it, and how Blocks 6 to 14 do:

1. **What is not about the region is a shared part,** where the region
   uses it: the region's tests then exercise it.
2. **What the region does not use is not written.** `docs/ui.md` lists
   the plain builders that have no part yet. The block that first
   needs one writes it under `ui/src/shared/` and adds its row.
3. **A shared part that lacks a variant gets a property,** not a copy
   in the region.
4. **A block's gate says** what it reused, what it added to the shared
   parts, and what it kept to itself and why.
5. **A second reader checks it before the gate,** against the plain
   code the later blocks will move. In Block 5 that reading found nine
   things in the Cubes' files that were not about Cubes; they are
   shared now.
6. Two blocks side by side may need the same missing part: the second
   to merge takes the first's.

## Different from the plan

1. **Who did it.**
   A sub-agent on Opus 5.5 wrote it in the session's own worktree,
   without a commit, and reworked it after the reading for reuse; the
   commits were made from recorded trees after the gate.
2. **Three commits for the block,** then the test of D178 and the
   contract's line of D180: the required fields; the shared parts,
   which draw nothing yet; the Cubes.
3. **The fault and D126's two defects are one fix.** With one drawing
   for the build and the update, both defects go with the same move.
4. **More shared parts than the plan lists:** the region's load
   counter, the icon choice as a signal, the plain island, the fold,
   the dropdown, the action runner, the link, the form's footer, the
   text field and the switch with their draft, the notice, the copy
   elements, a device's identifiers, and `register` with `mounter`.
5. **No change to the fixture for the guard.** Block 3's NOTE asked
   for a problem that is there from the start. The guard's Cube views
   stub `GET /api/v1/cubes` with one answer at every load instead: a
   low battery, a file difference, a Cube found elsewhere, a failing
   proxy and found Cubes.
6. **`pairing.js` changed,** although pairing stays plain: its state
   is its own (`pairingUI`), and it fills the panel's `.cube-pairing`
   in place, where it replaced the element before.
7. **Behaviour beside the fixes:**
   - the hidden-devices list follows the stored list until the user
     touches it, where it was a snapshot;
   - a value typed that equals the newly stored one counts as taken,
     without a "changed meanwhile";
   - the "changed meanwhile" notice is the shared field's: its class
     is `field-meanwhile`, its texts `field.changedMeanwhile` and
     `field.takeTheirs`.
8. **`pending_radiograms` is a property of the Cube's schema.** It
   stood at the level of a response, where no schema read it.
9. **`tools/ui-split/map.txt` still names `cube-panel.js`.** It is
   Block 1's record; nothing runs the tool on the tree as it is now.
10. **The merge of main** met one conflict, in the OpenAPI file: main's
    `confirmation` of a command's answer is kept.

## For the blocks that move a region

- **Every part of a region calls its counter's `use()`.** A part that
  reads a signal is not drawn again with its parent while its
  properties are the same; `use()` reads the load counter, the
  language and the icon choice.
- **A plain piece inside a part is an `Island`.** The plain code fills
  the element. Where it replaces the element itself, the island
  breaks: Preact keeps the one it made.
- **A `details` is a `Fold`.** It leaves out the toggle event that
  comes when a `details` is made open.
- **A field that shows stored data takes a draft** (`useDraft`,
  `TextField`, `Switch`); a free field keeps a state of its own.
- **A request under way that must outlast its part** is `live` state,
  not `useBusy`.
- **Two files of a region may not differ by case alone:** the bundler
  resolved `./actions` to `Actions.tsx`.
- **Where the fixture lacks what a guard view needs,** the view stubs
  the GET with one constant answer.
- **At 390 px an open problem list covers the next click:** a guard
  view presses Escape first.
- **A section card's badges stay plain** until the page's chrome moves
  (Block 14).
- **Block 6:** the header still calls the plain `foundWhat`,
  `joinParts` and `hostPort` of `cubes.js`. Their TypeScript twins are
  in `ui/src/cubes/` (`Found.tsx`, `util.ts`): the header's move keeps
  those and deletes the plain ones. `cubeEntry` is declared in
  `ui/src/plain/header.d.ts`.

## Defects found outside the block

Not fixed:

- The `Budget` schema lacks `max_memory_slots`, which the server
  sends.
- Signing out leaves the Cubes list as the last user saw it, until
  the next load. It was so before the move.

## What verified it

- **The new tests on the page before the change:** 20 failures, in the
  sub-agent's run; they pass after it.
- **That the guard bites:** with a Cube's head built again on purpose,
  at 1100 px in English, the Cubes list failed with 22 failures and
  Cube settings with 14, in the sub-agent's run.
- **Reuse:** no shared file imports from a region, and
  `TestSharedPartsKnowNoRegion` fails on a planted import of a region
  and of a library.
- **Before the merge of main:** eighteen UI test files in all four
  cases, 380 passed and 68 skipped, in the sub-agent's run.
- **After the merge of main:** `make ui`, gofmt, `go vet` for linux,
  windows and darwin, `MASSIMO_ENV_FILE=/dev/null go test ./...`,
  `make cross`, `make ui-check`, the types' `-check` and the
  guidelines' twelve checks pass.
- **UI tests after the merge of main:** ten test files in all four
  cases, 235 passed and 68 skipped. One failed once:
  `test_the_choice_in_my_settings` at 1100 px in English, a click on
  the page menu that timed out after 5 s while a cross-compile ran
  beside it, at a load of 26. It passed when run again, and its file
  passed twice more in all four cases.
- **Not run:** the whole UI suite, which is CI's and the first whole
  run of a region as parts; `make race`; `make lan-test`.
