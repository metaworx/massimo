# NOTE UiParts v1.0: block 10 after its ci

What the pull request of Block 10 (#389) met in CI after the NOTE on how the block went
was written, and what follows from it for the blocks still to come.
It adds to `GUIDELINES/wip/2026-11-21_01-10_NOTE_UiParts_v1.0_how_block_10_went.md`.

## What failed

All four UI jobs of the pull request's first run.

1. **The notifications card,** in every case:
   `test_notifications.py::test_this_browser_on_and_off`
   and `::test_another_device_removed`, with "fmtWhen is not defined".
   `notify.js`, plain until Block 13,
   shows when a device was added and last reached with `fmtWhen`,
   a plain global of `backup.js`.
   The block had moved it into `src/backups/` and removed the plain one.
2. **The focus after Keep,** once, in one case, and passed when run again:
   `test_users.py::test_a_double_click_on_yes_removes_once`.
   `useAsk` gave the focus back to the button that asked in an effect,
   which runs after the next frame;
   the plain question gave it at once, and the test reads it at once.

## Why no local run saw it

The local runs took the test files the block touched and those its brief named,
in all four cases; the whole suite was left to CI.
`test_notifications.py` was in neither list:
nothing said that the notifications card called into `backup.js`.
A sub-agent that ran the suite from a copy for another question had seen
both notification tests fail and took it for an effect of the copy;
the coordinating session did not follow it up.

## The fix

One commit on the pull request's branch,
"fix(ui): The notifications card finds its time format again",
made in a copy of the branch, the session's worktree being Block 12's by then:

- **`fmtWhen`** is the parts' own in `shared/time.ts`;
  `backup.js` keeps a plain `fmtWhen` that calls it through `MassimoParts.fmtWhen`,
  until Block 13 takes the card's last plain caller away.
- **`useAsk` and `Question`** give the focus in a layout effect,
  in the turn of the drawing that takes the question away or shows it,
  for every question drawn with them, those of the blocks before too.
  The test is unchanged.
- **Every plain name the block removed was looked up:**
  99 top-level names of `users.js`, `roles.js`, `providers.js`,
  `integrations.js` and `backup.js`; `fmtWhen` alone had a caller left.
  The first look had missed it,
  since `connect.js` has a `fmtWhen` of its own, for another page.
  The other way round, no plain script of the page calls a name
  that neither a plain script nor `src/plain/` declares.

## What verified it

In the copy:
the whole UI suite in two cases, 1100-en and 390-de:
442 passed, 1 skipped, each;
`test_notifications.py`, `test_users.py`, `test_admin_updates.py`
and `test_backup.py` in all four cases: 244 passed;
the focus test ten times in all four cases: 40 passed.
The pull request's second run was green, and it was merged.

## For the blocks still to come

- **Every top-level name of a plain script**
  that a block removes or moves into a part is looked up in every plain script,
  `index.html`, the partials and `connect.html`,
  page by page: a name of the same spelling on another page is no definition.
  A name still called stays, as a plain name that calls the part;
  the builder's report lists them.
- **The whole UI suite runs in one case** on a block's last tree,
  besides the touched files in all four.
- **A failure a sub-agent names in passing** is followed up before the push.
- **What the plain code did at once** (the focus given, a value read)
  is done in the drawing's own turn, a layout effect, not an effect.
