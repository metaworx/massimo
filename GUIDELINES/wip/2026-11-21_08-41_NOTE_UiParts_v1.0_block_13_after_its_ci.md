# NOTE UiParts v1.0: block 13 after its ci

What the pull request of Block 13 (#392) met in CI after the NOTE on how the block went
was written, and what follows from it.
It adds to `GUIDELINES/wip/2026-11-21_08-03_NOTE_UiParts_v1.0_how_block_13_went.md`.

## What failed

One UI job of the pull request's first run, 1100-en, in one test,
which passed when CI ran it again alone;
CI counts that as flaky and fails the run.

`test_integrations.py::test_why_not_where_the_variable_decides`
read "This server does not look for Home Assistant on the LAN."
where the found answer it had changed says that `MASSIMO_ANNOUNCE` decides.
The test and its region, System settings → Integrations, are Block 10's;
Block 13 changed neither.

## Why

The test's helper `found_box()` took the first paragraph in Seen on the LAN
as the sign that the found answer was drawn.
Since Block 10 the box is a part:

- it draws why the server does not look as soon as the list of integrations is in,
  before the found answer, which the region's refresh reads last;
  so on a fresh page the paragraph is there with the general text;
- it keeps the box through a new read;
  so at a second showing the paragraph is there with the earlier answer's text.

While the box was plain it was built anew at each read,
and a paragraph meant the answer.
No local run had met it: it needs the found read to answer late.

## The fix

One commit on the pull request's branch,
"test(ui): The Seen on the LAN tests wait for the answer they read",
made in a copy of the branch, the session's worktree being Block 14's by then.
`found_box()` catches the found read that its showing of System settings starts,
waits for its answer and for the part to have drawn it,
and only then hands the box over; its three callers follow.
Nothing of the page changed.

## What verified it

In the copy:
`test_integrations.py` in all four cases: 20 passed;
the three tests that use `found_box()` twenty times in all four cases:
240 passed, none failed.
With the found read held for a second and a half,
the helper as it was failed with the text CI showed, and the new one passed.
The pull request's second run was green, and it was merged.

## Seen in the page and left

- **The card shows the general text for a moment** before the found answer is in,
  on a fresh page: "does not look" without its reason.
- **The region's reads have no rule that the latest wins:**
  where two showings of System settings overlap
  and the read that started first answers last, the older answer stays.
  The tests cannot meet it, since each waits for its own read.

## For the blocks still to come

- **An element is no sign of fresh data in a part:**
  a test that changes an answer waits for the read it caused to be answered and drawn,
  not for an element the part keeps.
  Every such wait in the suite was looked at:
  this helper was the only one that could read stale.
- **Where a region becomes a part,** its tests' waits are read again for this,
  in the same block.
