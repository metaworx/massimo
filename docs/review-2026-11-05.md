# Code review, 2026-11-05 (phase-0 at 4c5308e)

A review of consistency, duplication, documentation, logic,
security and data safety,
done at the end of the session that built most of the code.
`go vet` and `gofmt` are clean, all tests pass.
Findings are ordered by weight within each section;
each one says where and what to do.
Nothing here is a blocker for LAN use behind a token;
the first three security items are the ones to do before any exposure beyond the LAN.

## Security

1. **Token comparison is not constant-time** (internal/server/server.go,
   the `api` wrapper).
   Fixed the same day: `tokenMatches` uses `crypto/subtle.ConstantTimeCompare`.
2. **No rate limit or lockout on the token check.**
   With the API on a LAN address this is acceptable;
   before any wider exposure add a per-IP limit on 401s.
   Fixed the same day: ten failed checks from one address within a minute lock
   it out for five minutes (429 with Retry-After), internal/server/auth.go.
3. **`?token=` on the event stream** puts the token into URLs,
   browser history and reverse-proxy logs.
   Mitigated by limiting it to that one route;
   the clean fix is a short-lived stream ticket issued by an authenticated call.
   Fixed the same day: `POST …/events/ticket` issues a single-use ticket valid
   for a minute; `?token=` still works, marked with a Deprecation header,
   until the web UI has moved to tickets.
4. **The LAN proxy and discovery have no authentication**,
   by the nature of the Cube protocol.
   `serve` binds the proxy to all interfaces by default.
   Document the firewall expectation (done in docs/proxy.md) and consider
   defaulting the proxy to the interface of `MASSIMO_CUBE_<SN>_PROXY` when that
   is set (partly done: with the variable set, that address is used).
5. **Pass-through of `t:` and `m:`** from proxy clients:
   a client can delete devices and rewrite the metadata.
   The metadata merge keeps the hidden devices, but `t:` is forwarded as is.
   Consider refusing `t:` for hidden devices.
   Fixed the same day: the proxy drops hidden devices from a `t:`,
   logs the refusal and forwards the rest,
   or answers the client itself when none is left.
6. **Web UI**:
   the token lives in localStorage;
   the page never builds HTML from API strings (textContent throughout,
   checked in the UI rounds), so an XSS would need another vector.
   Keep that rule.
   No cookies, hence no CSRF surface.
   Fixed the same day: ui.go sends `Content-Security-Policy: default-src 'self'`
   (images also `data:`, no framing),
   `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`;
   the page loads without console errors under it.
7. **`legacy -out`** saves the original software's complete output,
   which can contain portal credentials the software logs.
   The README says to treat the file as sensitive;
   the filter output on screen is already free of them.
   Fine, keep the note.
8. **`.env` is read from the current directory** by every command.
   Running a command inside an untrusted directory would load its `.env`.
   Acceptable for a command-line tool;
   `-env` and `MASSIMO_ENV_FILE` exist for fixed paths.
9. Dependencies: only `gopkg.in/yaml.v3` beyond the standard library.
   Run `govulncheck` in CI once it exists.
   Done since: govulncheck runs in CI for Linux and Windows;
   `golang.org/x/sys` (Windows service manager) was added at v0.41.0,
   the newest that builds with the Go 1.24 of go.mod.
   Its GO-2026-5024 (`NewNTUnicodeString`) is not reached;
   the fix needs v0.44.0 and with it Go 1.25 in go.mod.

## Data safety

1. **Writes to devices are guarded**:
   the queue checks duty cycle and memory slots, coalesces by key,
   and `restore` has `-dry-run` and a confirmation;
   room commands to rooms with members without state are reported with `no_state`.
   Good.
2. **The ghost room (255) is protected** in restore,
   the API and the proxy's metadata merge,
   and since security 5 against a `t:` from a proxy client.
   Not protected: a direct `cube` raw command, which is the expert's own risk.
3. **Snapshot mirrors after writes** (metadata via `ApplyLocal`,
   device config via a `c:` re-read) are optimistic:
   a write the Cube acknowledged but did not apply would leave the snapshot
   wrong until the next reconnect.
   The reconnect on every `serve` start resets it.
   Acceptable; a periodic full refresh (reconnect every N hours or a `c:` sweep)
   would make it robust.
   Fixed the same day: `serve` reconnects to each Cube every six hours (`-refresh`,
   0 off) as a queue command,
   and a greeting now also drops devices the Cube no longer reports.
4. **Backups** never contain keys, IVs or tokens;
   they contain names and serials and the raw lines,
   and are gitignored by pattern.
   The firmware dumps are gitignored too.
5. **Pending radiograms to never-answering devices** occupy Cube memory slots for hours;
   the queue's `MinFreeSlots` policy prevents filling the Cube up.
   The restore planner no longer links contacts to each other,
   which caused most of those.
6. **Config output** redacts keys, IVs and tokens;
   names and addresses are shown, which is intended.

## Logical consistency

1. **`MANU` on a room with an unknown setpoint sent 20 °C.**
   Fixed the same day: MANU now explains that no setpoint is known and leaves
   the choice to the stepper, which sends manual itself.
2. **Pending radiograms assumed 50 memory slots.**
   Fixed the same day: the budget tracks the highest free-slot count a Cube ever
   reported (`MaxSlots`, at least 50) and counts pending radiograms against it.
3. **Room-level configuration writes use the first device as the queue's
   error-reset target**, so a second device in error state is not reset.
   Documented in config_api.go;
   a per-device command would fix it at the cost of one wakeup per device.
4. **`serve -sn`** restricts to one Cube while every other command uses `-sn` to
   select the Cube's variables; consistent in effect,
   but the README should say both in one place (it does under Versions and proxy;
   move it to the per-Cube paragraph).
   Fixed the same day: both meanings sit under the README's "Cube variables" table.
5. **Ignore list vs ghost room**:
   two mechanisms for the same thing, one configured, one by convention.
   Keep both for now; when settings move to a database, fold the list into it.
6. **Version check reload** in the UI skips when a panel is open;
   the settings page counts as open,
   so a user who leaves settings open never auto-reloads.
   Intended, but worth a note in the settings page.
7. **UI mode detection for a room** takes the first thermostat's mode;
   rooms with devices in different modes (possible after a direct device command
   from another client) show only one.
   Show "mixed" when they differ.

## Code duplication

1. **Device state view** was built three times from `cube.DeviceState`.
   Fixed the same day: `backup.StateOf` is the one constructor, used by the API,
   `status` and backups.
2. **`m:` to `M:` conversion** for the snapshot mirror was in proxy.go,
   server.go and config_api.go.
   Fixed the same day: `cubelan.Client.ApplyMetadataWrite` is the one implementation.
3. **Hidden-room computation** exists as `backup.Ignored.HiddenRooms` and,
   for the proxy's room-255 rule, in `proxy.hiddenRooms`;
   status.go and server.go repeat the "room with only hidden devices" filtering.
   One helper returning visible rooms and devices for a snapshot would remove four copies.
   Fixed the same day: `view.Hidden` with `Rooms`, `VisibleRooms` and `Room`,
   and `view.Rooms`/`view.Devices`, used by the API, status,
   backups and the proxy.
4. **Per-Cube variable lookup** is implemented in `cubeEnv` (env.go) and again
   inline in serve.go for `_IGNORE`, `_NAME`, `_PROXY`, `_PROXY_SERIAL`.
   Give serve a `perCube(name, sn)` helper that falls back to the plain name for
   a single Cube.
   Fixed the same day: `env.Get` (plain fallback) and `env.Own` (plain fallback
   for a single Cube only), used by serve and every other command.
5. **Room-ready logic** (`neverReported` in server.go,
   the `ready` flag in status.go and in `rooms`) is the same rule in three places.
   Fixed the same day: `view.Silent`,
   which both the ready flag and the `no_state` list use,
   by the Cube's own group membership (C line).
6. **UI**:
   tiles.js, config.js and app.js each have their own small helpers for API
   calls with the token, number formatting and badge creation;
   move them to app.js and share.

## Code consistency

1. Error responses: `fail()` for most,
   a bare `return err` for a few internal errors in config_api.go,
   which the wrapper maps to 500 with the raw message.
   Route them through `fail` with 502 where they come from the Cube.
   Fixed the same day: all through `fail`;
   an error that still bypasses it is logged.
2. Naming: `Ignored`/`Hidden`/`ghost` are used for one concept;
   settle on "hidden" in code comments and docs,
   keep `IGNORE` in the variable name for compatibility.
   Fixed the same day, identifiers included (`cube.HiddenRoom`, `ShowHidden`,
   `-show-hidden` with the old flags as aliases).
3. Command-line flags: `-addr` means the Cube on most commands and the listen
   address on `portal`/`fakecube`; `serve` has `-listen`.
   Rename the listener flags to `-listen` everywhere.
   Checked the same day: `portal` and `fakecube` already take `-listen`,
   and no command uses `-addr` for a listener, so no alias was needed.
4. Logging: slog with key-value pairs everywhere in Go;
   the UI logs to the console only on errors.
   Fine.
5. Tests: every package has tests except `cubelan/fakecube` (used by tests of
   others) and the UI's JavaScript (verified by Playwright runs that are not checked in).
   Add a Playwright smoke test under a build tag or a `make ui-test` target that
   starts the fake Cube and the server and checks the page loads without console errors.

## Should code be extracted into common modules?

Yes, three extractions, all inside this repository (no separate modules yet;
the module boundary `go.metaworx.ch/massimo` is right for one binary):

1. **`internal/view`**:
   the read model shared by the API, `status` and backups:
   device state from a snapshot, visible rooms and devices given the hidden set,
   the room-ready rule, the pending count.
   Today these live in `backup`, `server` and `cmd/massimo/status.go`;
   the duplications listed above all disappear into this one package,
   and `backup` stops being imported for its `State` type by the server.
   Done the same day.
2. **`internal/cubeio`** (or methods on `cubelan.Client`):
   "write metadata and mirror it",
   "write a device config and re-read its C line", "move a device",
   used by the API, the proxy and the restore planner.
   The planner's `MoveCommands` already went this way;
   the metadata and config helpers in config_api.go and proxy.go should follow.
   Done the same day as `internal/cubeio` (`Writer.Do`, `WriteMetadata`,
   `Reread`, `MoveCommands`, `KeepHidden`);
   the restore planner runs its steps through it too.
3. **`internal/env`** for the command line: the per-Cube variable lookup,
   the `.env` loader, the hidden set and the proxy-first address resolution,
   so that `serve` and the other commands share one implementation and a future
   settings database can replace it in one place.
   Done the same day.

Not worth extracting: the protocol package (already the right boundary),
the queue, the proxy.
A separate Go module for the protocol package can come when another program wants it;
nothing is gained earlier.

## Coding standard

What the code base follows today,
written down so that the next sessions keep it:

- Go 1.24, standard library first; one external dependency (`gopkg.in/yaml.v3`).
  `gofmt` and `go vet` clean on every commit; all tests pass; no `//nolint`.
- Files start with the SPDX line `AGPL-3.0-or-later` and the copyright line;
  JavaScript and CSS carry a one-line licence comment.
- Package comments explain what the package is for; every exported
  symbol has a comment that is a sentence; unexported helpers get one
  when their name does not say it.
- Errors: wrap with context (`fmt.Errorf("serve: %w", err)`), sentinel
  errors in the package that defines the condition (`engine.ErrDiscarded`),
  HTTP errors through `fail(status, …)`; never panic on input.
- Protocol bytes are built only in `internal/protocol/cube` and tested
  against captured lines byte for byte; a command the hardware has not
  confirmed is marked so in its comment and in docs/portal-protocol.md.
- Hardware findings go into docs/portal-protocol.md the day they are made,
  with the date and the Cube firmware.
- Logging with `slog` key-value pairs, Info for events a user wants in the log,
  Warn for anything the Cube refused, Debug for per-line traffic.
- Secrets never in code, fixtures, docs, logs or commit messages; keys,
  IVs and tokens are redacted in every printout; real room and device
  names only in the owner's pastes, never in the repository.
- Tests use the fake Cube with the recorded greeting;
  no test needs hardware or the network.
  New endpoints get a test that checks the exact line sent to the fake Cube.
- Web UI: plain HTML, CSS and JavaScript, embedded with `go:embed`,
  no build step, no framework, no inline event handlers,
  API text only via `textContent`,
  CSS variables for colours with light and dark, phone width first,
  every icon-only control labelled, keyboard operable,
  verified with Playwright against the fake Cube at 1100 px and 390 px before a merge.
- Commits: a short subject in the imperative, a body in sentences saying why,
  the attribution lines at the end; one feature per tag (`make tag`).
- Documentation moves with the code: README for the command line,
  the API documents for every route,
  the proxy and firmware documents for their topics,
  the roadmap and the handover at the end of a session.
