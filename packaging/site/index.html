Massimo

Open-source successor software for eQ-3 MAX! heating systems (the MAX! Cube LAN gateway, radiator and wall thermostats, window contacts, eco switches) after the vendor's end of life.

One program, massimo serve, on a small box on the Cubes' network (a Raspberry Pi 1 is enough) gives them a web UI for phone and desktop, a JSON API, and a proxy through which the original MAX! software keeps working. It runs on your own hardware, with no account and no cloud. Massimo is in early development: every release is a pre-release on the update channel alpha.

Install

Debian, Ubuntu, Raspberry Pi OS: the apt repository

One suite per update channel: {{SUITES}}. Install the keyring package first, then the sources:

curl -fsSLo /tmp/massimo-archive-keyring.deb https://massimo.metaworx.ch/apt/massimo-archive-keyring.deb
sudo apt install /tmp/massimo-archive-keyring.deb
sudo tee /etc/apt/sources.list.d/massimo.sources <<'EOF'
Types: deb
URIs: https://massimo.metaworx.ch/apt
Suites: alpha
Components: main
Signed-By: /usr/share/keyrings/massimo-archive-keyring.gpg
EOF
sudo apt update && sudo apt install massimo

Put a line into /etc/massimo/env, such as the token (see The first settings), then sudo systemctl start massimo; sudo apt upgrade installs each release from then on. A single release's package is also on the releases page: _arm64.deb for a 64-bit Raspberry Pi OS, _armhf for a 32-bit one (the Pi 1 included), _amd64 for a PC. The repository's key, for a check by hand, is massimo.asc. A box that followed the old address https://metaworx.github.io/massimo/apt changes its sources once: Moving from the old address. Details: The apt repository.

macOS: Homebrew

brew install metaworx/massimo/massimo-alpha
brew services start massimo-alpha

Homebrew builds the release from source. The settings are in $(brew --prefix)/etc/massimo/env, and brew upgrade massimo-alpha updates it. Details: Homebrew.

Windows: the service

Download massimo-windows-amd64.exe from the releases page. Then, in PowerShell opened with "Run as administrator", in that folder, with a settings file .env next to it (an empty one will do, see The first settings):

.\massimo-windows-amd64.exe install -dry-run -settings .env
.\massimo-windows-amd64.exe install -settings .env

This installs the service massimo and its firewall rule; the web UI's button and massimo update install the next release. The binary is not code-signed: one downloaded with a browser meets SmartScreen's "Unknown publisher" when started from Explorer. Details: Windows.

Linux and macOS: the binary as a service

Every release carries one binary per platform, with SHA256SUMS and a signed manifest, on the releases page; Installing says which binary fits which box. As root, in the folder with the binary (here the one for a 64-bit Raspberry Pi) and a settings file .env (an empty one will do, see The first settings):

chmod +x massimo-linux-arm64
sudo ./massimo-linux-arm64 install -dry-run -settings .env
sudo ./massimo-linux-arm64 install -settings .env

This installs a systemd service on Linux, a LaunchDaemon on a Mac; the web UI's button and massimo update install the next release. Details: Install with massimo install.

The first settings

On the Cubes' network the server needs no settings to begin with. Open http://<the box>:8099/ from a device on the same network: while there are no users, the page offers the local network a form for the first owner. Then add the Cubes under System settings → Cubes, which lists those the server finds. A Cube takes one client at a time: close the original MAX! software first; from then on that software connects to the server's proxy.

The settings file each route above names takes what discovery and the page cannot give: the address of a Cube that discovery does not reach, on another subnet or behind a VPN (massimo discover lists the Cubes it hears, with their serial and address), and a token that becomes the owner's key at the first start, which the page then asks for, so that no form for the first owner is open on the network:

MASSIMO_CUBE_KEQ0000000_ADDRESS=192.168.1.10
MASSIMO_API_TOKEN=choose-a-long-random-string

The Debian package starts the service, and restarts it after an upgrade, only once /etc/massimo/env differs from the template, so that a fresh box does not serve the network unasked: put a line in, such as the token, then sudo systemctl start massimo. massimo install -settings .env starts it with that file, an empty one too. Details: Server.
